# Pablo 작업별 실행 규칙

아래 경로는 Pablo 루트 기준이다. 필요한 절만 읽고 실행한다. Huashu 자료는 `references/pablo-adapter.md`의 허용 범위로 참조한다.

## 탐색용 시안 범위와 고도화 질문

[디자인 대화 흐름](pablo-design-dialogue.md)에서 탐색이 필요하다고 판단한 경우에만 아래 대표 범위를 세 방향으로 제작한다. 대표 시안은 최종 납품 수량과 구분해 표시한다. 사용자가 전체 시안이나 다른 비교 범위를 지정하면 그 범위를 따른다. 질문은 선택한 실제 시안에서 미결인 항목만 고른다.

| 작업 | 방향별 비교용 시안 | 선택 후 확인할 항목 예시 |
|---|---|---|
| IR Deck | 동일 내용의 대표 2장: 표지 + 본문/데이터 페이지 | 발표용·읽기용, 정보량, 강조할 메시지 |
| UI·랜딩페이지 | 첫 화면 + 핵심 섹션/동작; 한 화면 요청이면 그 화면 안에서 비교 | 주요 행동, 정보 우선순위, 필요한 상태·모션 |
| 아키텍처 | 동일 노드·연결을 담은 다이어그램 | 독자, 상세 수준, 강조할 흐름 |
| PPT 리뷰·수정 | 전면 재설계 요청일 때만 같은 대표 슬라이드의 디자인 3안 | 기존 요소 보존, 정렬·밀도, 발표 환경 |
| 브랜드 적용 | 원본 형식의 대표 화면/페이지; 모든 안에 동일한 브랜드 제약 적용 | 유지할 요소, 허용된 변형, 브랜드 표현 강도 |
| 모션 요청이 결합된 작업 | 각 방향의 짧은 실제 동작 데모 + 대표 정지 화면 | 강도·속도, 재생·정지, 모바일·모션 줄이기 |

일반 PPT 리뷰와 국소 수정은 원래 범위를 유지한다. 비교 단계에서 만든 2장 덱을 요청한 10장 최종 덱으로 보고하지 않는다.


<a id="ir-deck"></a>
## IR Deck

**입력:** 제공된 회사·제품 자료, 투자 대상 독자, 지정 장수, 기존 템플릿/브랜드.

- 먼저 근거 자료에서 핵심 주장과 수치를 추출하고 슬라이드별 메시지를 배치한다. “10장”은 표지와 마지막 장을 포함한 정확히 10장이다. 요청되지 않은 부록으로 장수를 늘리지 않는다.
- 구성이 미지정이면 10장 기준 표지·투자 요약 / 문제 / 솔루션 / 제품 / 시장 / 사업 모델 / 성과 / 경쟁·차별점 / 팀·실행 계획 / 투자 요청을 출발점으로 삼되 제공 자료에 맞춰 조정한다.
- 시장 규모, 매출, 성장률, 고객, 투자 유치액은 근거가 있을 때만 넣는다. 부족한 값은 미확인 표시 또는 자료가 있는 내용으로 구성한다. 차트 수치와 단위·기간을 원자료와 대조한다.
- 슬라이드에 맞는 사용 가능한 프레젠테이션 도구·스킬을 활용한다. HTML 경로를 택하면 `references/slide-decks.md`와 `references/editable-pptx.md`를 읽고 변환 가능한 구조로 작성한다. 기존 시각 HTML을 변환할 때만 `references/pptx-from-rendered-html.md`를 참고한다.
- 기본 납품은 PPTX와 PDF 미리보기다. 사용자가 다른 형식을 지정하면 그 형식을 따른다. 글자와 핵심 도형은 편집 가능하게 유지하고 이미지로 들어간 요소는 구분한다.
- 모든 슬라이드를 렌더링하여 잘림·겹침·한글 폰트·대비·정렬을 확인하고 최종 장수와 수치를 다시 검증한다.

<a id="ui-mockup"></a>
## UI 목업

**입력:** 스크린샷, 화면 설명, 기존 디자인/소스, 대상 기기.

- 주어진 화면의 정보 구조, 주요 행동, 상태를 파악한다. 한 화면 요청은 한 화면으로 만든다. 모바일이라는 이유로 여러 화면으로 늘리지 않는다.
- 입력이 스크린샷뿐이면 보이지 않는 동작을 구현 사실처럼 설명하지 않는다. 요청 목적에 필요한 동작을 명시적인 데모 동작으로 만든다.
- 기본은 브라우저에서 확인할 수 있는 HTML/CSS 또는 React 목업이다. 기기 프레임이 필요할 때만 `assets/ios_frame.jsx`, `assets/android_frame.jsx`, `assets/browser_window.jsx`를 사용한다.
- 모바일 구현은 `references/app-prototype.md`, React 구성은 `references/react-setup.md`의 필요한 구현 부분을 참고한다. 이들 문서의 화면 수 기본값보다 사용자 범위를 우선한다.
- 요청된 화면 크기로 렌더링하고 주요 클릭·입력·상태 전환을 검사한다. 외부 API 연동이 없는 데모임을 구분한다. 소스와 미리보기를 함께 전달한다.

<a id="architecture"></a>
## 시스템 아키텍처

**입력:** 시스템 설명, 다이어그램, 명시된 저장소/설계 문서.

- 구성 요소, 시스템 경계, 연결 방향, 프로토콜, 데이터 저장소, 외부 연동을 근거 자료에서 추출한다. 현재 구조와 개선안을 요청에 맞춰 분리한다.
- 간단한 관계는 Mermaid, 배치·브랜드·복잡한 경계 표현이 중요하면 SVG 또는 HTML을 사용한다. 편집 가능한 원본을 남긴다.
- 구성 요소와 연결선이 실제 자료에 있는지 확인한다. 추론한 연결은 “추정/확인 필요”로 표시하며 임의로 DB·큐·클라우드 서비스를 추가하지 않는다.
- 경계와 범례, 주요 데이터 흐름 방향을 표현하고 선 교차·라벨 겹침을 줄인다. 기술적으로 같은 의미를 가진 항목에는 일관된 표기를 사용한다.
- 렌더링 결과를 확인하고 설명과 다이어그램의 노드·연결·경계를 대조한다. 이미지 출력이 요청되면 SVG/PNG 등 실제 출력 파일도 제공한다.

<a id="ppt-review"></a>
## PPT 디자인 리뷰·수정

**입력:** PPTX 또는 연결된 프레젠테이션. PDF·이미지만 있으면 시각 리뷰는 가능하지만 원본 PPTX 구조를 보존한 수정은 할 수 없음을 구분한다.

- 전체 슬라이드를 읽고 렌더링한 후 흐름, 메시지, 시각 계층, 가독성, 정렬, 차트, 브랜드 일관성을 평가한다. `references/critique-guide.md`는 평가 관점으로 활용한다. 특정 스타일 취향만으로 감점하지 않는다.
- 결과는 슬라이드 번호·관찰된 문제·수정 내용·중요도로 정리한다. 요청되지 않은 점수표나 레이더 차트는 만들지 않는다.
- “리뷰”는 진단으로 끝낸다. “리뷰하고 수정”은 원본 사본에서 수정하고 최종 PPTX를 납품한다. 이미 허용된 수정에 재승인을 요구하지 않는다.
- 숫자·주장·슬라이드 순서와 수, 발표자 노트·링크·마스터 등 관련 원본 구조를 보존한다. 도구가 일부 요소를 보존하지 못하면 손실을 숨기지 않고 지원되는 경로를 찾는다. 보존이 불가능한 경우 재구성본을 원본 보존 수정본으로 부르지 않는다.
- 텍스트와 도형을 전체 슬라이드 이미지로 평탄화하지 않는다. 수정 전후 내용을 비교하고, 모든 수정 슬라이드와 영향받은 공통 레이아웃을 다시 렌더링한다.
- 리뷰 요약, 수정 PPTX, 미리보기, 보존하지 못한 요소가 있다면 그 목록을 제공한다.

<a id="rebrand"></a>
## 회사 브랜드 적용

**입력:** 기존 디자인 + 회사의 브랜드 가이드/템플릿/로고/기존 승인 자료.

- 회사명과 브랜드 자료가 대화나 파일에 있으면 먼저 사용한다. 회사가 특정되지 않으면 사용자에게 회사를 확인한다. 자료가 충돌하면 최신 승인 자료를 우선하고 판단 근거를 밝힌다.
- `references/brand-asset-protocol.md`의 자산 확인 방법을 활용해 실제 로고, 컬러, 폰트, 여백, 이미지 사용 규칙을 추출한다. 공식 자료가 없는 색상·폰트는 브랜드 규정으로 단정하지 않는다.
- 작업 폴더의 `brand-spec.md`에 사용한 자료와 적용 규칙을 기록한다. 이번 작업 자료를 전역 스킬 자산이나 공개 저장소에 복사하지 않는다.
- 색상 교체에 그치지 않고 글자 계층, 그리드, 도형, 이미지 처리, 차트와 로고 배치를 적용한다. 내용·수치·기능은 보존한다.
- 원본이 PPTX면 PPT 리뷰·수정의 보존 규칙, UI면 UI 검증, 아키텍처면 관계 검증을 함께 적용한다. 기본은 원본 형식의 새 버전이다.
- 브랜드 기준과 최종 렌더링을 대조하고 적용 항목과 자료 부족으로 확정하지 못한 항목을 전달한다.

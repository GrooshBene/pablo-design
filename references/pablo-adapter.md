# Huashu 기술 자료 사용 경계

Pablo 요청은 SKILL.md → pablo-workflows.md → 필요한 기술 자료 순서로 실행한다. 원본 Huashu 지침 전체를 다른 활성 스킬로 호출하지 않는다. 다음 표는 원본 문서를 수정하지 않고 재사용하는 범위를 정한다.

| 참조 | 가져올 기술 | Pablo에서 별도로 결정할 사항 |
|---|---|---|
| slide-decks.md | 페이지 레이아웃, HTML 조립, 출력 크기, 폰트·렌더링 주의점 | HTML 필수 납품, 출력 형식 재확인, 시안·중간 승인 단계 |
| editable-pptx.md | html2pptx를 선택했을 때만 DOM·크기 제약 | 요청된 PPTX를 PDF로 대체하거나 재작성을 강요하는 절차 |
| pptx-from-rendered-html.md | 기존 HTML의 좌표 추출·PPTX 변환 | 모든 템플릿 작업을 이 도구로 제한하는 규칙 |
| app-prototype.md | 컴포넌트, 상태 구현, 필요할 때 기기 프레임 | 4~6화면 강제, 모든 화면에 이미지·프레임 추가 |

보안·데이터 전송 동의와 변환 도구의 실제 기술 제약은 유지한다. 기존 문서의 상반된 변환 경로를 만났다면 입력 형식과 요청된 납품 형식으로 선택한다. 원본 PPTX 편집에는 HTML→PPTX 도구를 사용하지 않는다.

## 납품 게이트

1. 요청한 장수·파일 형식·화면 범위와 실제 파일을 비교한다.
2. 변환 중 오류가 하나라도 있으면 생성 파일이 있어도 미완료로 취급한다.
3. 원자료와 텍스트·숫자·관계를 대조한다. 자동 텍스트 검사는 텍스트 변환 경로에서 누락을 찾는 보조 수단이다.
4. 최종 PPTX를 실제 프레젠테이션 렌더러로 렌더링한다. HTML에서 만든 PDF는 PPTX 검증을 대체하지 않는다.
5. 샘플·시안·최종본 모두 [시각 품질 게이트](pablo-visual-quality.md)를 적용한다. 최종 이미지를 확인하고 잘림·겹침·가독성 문제를 수정한다. 편집 가능성과 노트·차트·링크 등 요구한 보존 항목을 별도로 검사한다.

## 디자인 진행과 도구 위임

탐색·선택·고도화는 [디자인 대화 흐름](pablo-design-dialogue.md)이 결정한다. 기술 자료나 제작 스킬을 호출할 때 현재 단계, 기준안 버전, 허용된 제작 범위를 함께 전달한다. 비교용 데모를 최종 제작으로 간주하지 않는다. 명시된 사용자 요청과 호스트 권한·보안 제한을 우선하며, 도구의 기본 자율 진행이나 자동 게시를 시안 선택·최종 확정의 대체로 사용하지 않는다. 외부 게시에는 해당 도구의 실제 접근 권한과 사용자가 허용한 공개 범위를 적용한다.

기존 `scripts/design-gate-hook.sh`는 선택적으로 설치하는 장편 영상용 파일 존재 검사다. Pablo의 단계·버전 승인 상태 검증기로 사용하지 않는다.

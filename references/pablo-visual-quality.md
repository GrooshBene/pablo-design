# Pablo Anti AI-slop 품질 기준

[UPSTREAM-DESIGN.md](../UPSTREAM-DESIGN.md)의 §6과 [content-guidelines.md](content-guidelines.md)의 시각 품질 원칙을 Pablo의 활성 제작 기준으로 유지한다. 샘플·설명용 예시·탐색 시안·최종 결과물 모두에 적용한다. “데모니까” 또는 “AI처럼 보이지 않게 색상만 변경”은 예외 사유가 아니다. 원본의 운영 절차·도구 지정까지 다시 활성화하지는 않는다.

## 제작 전: 내용에서 형태를 정한다

브리프에 다음을 적고 디자인한다: 독자가 먼저 알아야 할 메시지, 실제 내용에 맞는 정보 구조, 의도한 분위기, 제목/본문 서체와 언어 지원, 색상의 근거, 실제 제품 자산의 위치. 각 시안이 왜 이 내용에 맞는지 한 문장으로 설명할 수 있어야 한다. 확인된 브랜드·사용자의 명시적 디자인 지시를 우선한다.

## 기본적으로 배제할 패턴

| 패턴 | 제작 기준 |
|---|---|
| 범용 보라·핑크·파랑 그라데이션, 네온 glow로 채운 기술 제품 배경 | 브랜드·내용과 연결되는 색상과 명암을 사용한다. 어두운 배경이나 그라데이션 자체를 일괄 금지하지 않는다. |
| 제목·기능·버튼마다 붙이는 emoji 아이콘 | 텍스트 계층과 배치로 구분한다. 식별에 필요한 경우 실제 아이콘 자산·일관된 아이콘 체계를 사용한다. |
| 둥근 카드 + 왼쪽 컬러 테두리의 반복 | 글자 크기·굵기, 여백, 그리드, 구분선과 면 대비로 위계를 만든다. 둥근 버튼·카드 전체를 금지하는 규칙은 아니다. |
| SVG로 즉석에서 그린 사람·얼굴·장면 | 확인된 사진·제공된 일러스트 자산을 사용하거나 해당 표현을 생략한다. SVG 아이콘·로고·실제 데이터 차트·구조 다이어그램은 허용한다. |
| 실제 제품 사진 대신 CSS 실루엣·직접 그린 SVG 장비 모형 | 실제 제품은 제공 자료 또는 공식 자산을 우선 확인한다. 없으면 “제품 이미지 미제공”으로 명시하거나 꼭 필요한 자산만 요청한다. 모형을 실제 제품처럼 제출하지 않는다. |
| Inter·Roboto·Arial·시스템 폰트를 무심코 제목용 display에 적용 | 내용·브랜드·언어에 맞는 제목/본문 조합을 의도적으로 선택한다. 본문·UI 가독성용 시스템 폰트와 브랜드가 지정한 서체는 구분한다. |
| 모든 섹션이 동일한 3열 카드, 무의미한 배지·숫자·상승 막대, 상투적인 영문 캐치프레이즈 | 실제 내용의 관계에 맞춰 구성한다. 수치 없는 장식 차트와 창작한 성과·추천사는 제거한다. 예시 데이터가 필요한 작업이면 예시임을 분명히 표시한다. |

실제 디지털 제품을 소개할 때에도 임의의 대시보드를 제품 스크린샷처럼 제시하지 않는다. 새 UI를 설계하는 목업 작업은 허용하며, 설명용 UI 예시는 그렇게 표시한다. CSS Grid·SVG 다이어그램을 사용하는 것과 제품 실물 이미지를 모사하는 것은 다른 작업이다.

확인된 브랜드 가이드·사용자 요청이 위 패턴을 명시하면 해당 요소만 예외로 허용하고 근거를 기록한다. “브랜드에 어울릴 것 같다”는 추측은 예외가 아니다. 자료의 사실성과 이미지 출처를 허위로 표시할 수는 없다. Anti AI-slop 자체를 설명하는 반례는 별도 영역에 반례임을 표시한다.

## 적극적으로 사용할 제작 원칙

- **타이포그래피:** 제목에는 신중하게 고른 serif display를 우선 검토하고 본문과 역할을 구분한다. 기술 문서·브랜드 등 목적에 따라 적합한 다른 계열도 선택한다. 한글 글리프·굵기·실제 폰트 로딩을 확인한다. 영어만 serif이고 한글은 의도치 않은 fallback인 결과를 검증 완료로 간주하지 않는다.
- **줄바꿈·배치:** 웹의 본문에는 `text-wrap: pretty`, 제목에는 필요에 따라 `text-wrap: balance`를 사용한다. 페이지의 정보 구조는 CSS Grid로 설계하고 작은 일차원 정렬에는 Flexbox를 사용할 수 있다. 이 속성의 유무만으로 좋은 디자인이라고 판정하지 않는다.
- **색상:** 제공된 브랜드 색상은 그대로 보존하고, 새 색상 토큰과 명암 확장은 `oklch()`를 기본으로 설계한다. 대비·가독성과 렌더러 지원을 확인한다. 브랜드 HEX를 억지로 바꾸지 않으며, 지원하지 않는 내보내기 경로에는 같은 색의 sRGB fallback을 사용하고 최종 출력을 확인한다.
- **시각 자료:** 제공·공식 자산을 먼저 사용한다. 이미지 생성·외부 업로드는 사용자 요청과 도구의 권한 범위 안에서만 수행한다. 규칙 충족을 위해 불필요한 이미지나 외부 서비스 호출을 추가하지 않는다.
- **차별성:** 색상 교체, serif 하나 추가, 모션 장식만으로 세 안을 구분하지 않는다. 공통 내용은 유지하고 서로 다른 정보 배치·시각적 위계·사용 흐름이 렌더에서 읽혀야 한다. 크림색·녹색·세리프 조합 역시 자동 기본 템플릿으로 반복하지 않는다.

CSS 관련 원칙은 HTML/CSS 출력에 적용한다. PPTX·SVG 등 다른 형식에는 대응하는 정렬·타이포그래피·색상 원칙을 적용하며 CSS 사용을 형식적으로 요구하지 않는다. 기존 템플릿의 재현·부분 수정은 요청한 범위를 유지하고, 품질 규칙을 이유로 전체를 재설계하지 않는다.

## 제시 전 품질 게이트

각 시안의 실제 렌더를 보고 다음을 확인한다. 해당 결과물 폴더의 `visual-review.md`에 관찰, 수정한 항목, 남은 문제, 브랜드/사용자 지시로 유지한 예외와 근거를 짧게 기록한다. 병렬 작업자는 자기 폴더에 기록하고 담당 에이전트가 비교 전 다시 확인한다.

1. 금지 패턴이 남았다면 해당 요소를 수정한다. 확인된 예외가 없으면 사용자 선택용 완성 시안이나 최종본으로 제시하지 않는다.
2. 제품 사진·화면·수치가 실제 자료인지, 설명용 예시는 명확히 표시됐는지 확인한다. 필수 이미지가 없는 부분 시안은 한계를 표시하며 완성으로 보고하지 않는다.
3. 제목/본문 서체, 한글 fallback, 줄바꿈, 여백·정렬, 대비를 실제 렌더에서 확인한다. 필요한 화면 크기와 내보내기 형식에서 검사한다.
4. 세 안은 동일한 비교 범위에서 정보 구조·핵심 표현이 실제로 다른지 확인한다. 색상·폰트만 달라 보이면 차별성이 부족한 안을 다시 만든다.
5. 코드 검색은 의심 지점을 찾는 보조 도구다. 속성 존재 검사나 자동 점수만으로 미적 품질을 보장하지 않는다. 렌더를 확인하지 못하면 미검증으로 알린다.
